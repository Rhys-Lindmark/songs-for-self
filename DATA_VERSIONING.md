# Dataset versioning

Songs for Self treats the enriched playlist as a versioned research dataset, not an opaque build byproduct.

## Current contract

- `datasetVersion` follows semantic versioning. Patch releases add evidence or correct individual records without changing columns or top-level taxonomy. Minor releases add backward-compatible fields or generated artifacts. Major releases may rename or remove fields, change the taxonomy, or alter the meaning of a placement.
- `manifestSchemaVersion` versions the manifest itself independently.
- `data/dataset-manifest.json` records the four coverage denominators, the taxonomy contract, the newest source enrichment timestamp, and SHA-256 hashes for the canonical CSV, canonical visualization JSON, lightweight summary, lazy timeline, geography and genre-space artifacts, map outline, and browser-local upload lookup.
- `public/dataset-manifest.json` is the byte-for-byte published copy. Consumers can use it to verify downloaded artifacts and detect a stale deployment.

## Regeneration order

Run the following commands after a reviewed data change:

1. `npm run data:genre-overrides`
2. `npm run data:geography-overrides`
3. `npm run data:us-state-regions`
4. `npm run data:viz`
5. `npm run data:upload`
6. `npm run data:other-audit`
7. `npm run data:singleton-queue`
8. `npm run data:genre-evidence-gaps`
9. `npm run data:genre-space`
10. `npm run data:manifest`
11. `npm test`

The manifest must be generated last because it hashes the outputs from the preceding steps. A hash-test failure means an artifact changed without a corresponding manifest refresh; regenerate and inspect the diff rather than hand-editing a digest.
